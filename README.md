## Тема

**Task Tracker** — личный список задач со сроками и приоритетами.

Автор: Газ Артем Андреевич  
Группа: ФТ24ВР62ИВ

## Основной сценарий

Task Tracker помогает студенту вести личные задачи. Пользователь добавляет задачу, указывает срок и приоритет, меняет статус и находит просроченные записи. Теги помогают группировать задачи.

## Стек

- React
- TypeScript
- Vite
- React Router
- Supabase (Auth и личные задачи)
- позже: Node.js, Express

## Версия Node.js

`24.15.0` (файл `.node-version` в корне репозитория)

## Что работает сейчас (ЛР 6)

- Регистрация, вход и выход по email и паролю
- Личные страницы закрыты до входа
- Создание, просмотр, изменение и удаление задач в Supabase
- Записи сохраняются после обновления страницы и повторного входа
- Один фильтр по статусу
- Справочник тегов читается из Supabase
- Два аккаунта видят разные списки

Демонстрационные задачи больше не подмешиваются. В задаче хранится `id` тега, в списке показывается `name`.

## Модель доступа

| Таблица | Кто читает | Кто меняет |
| --- | --- | --- |
| `tags` | все, включая гостя | никто из браузера |
| `tasks` | только владелец | только владелец: select, insert, update, delete |

`owner_id` задаёт база из `auth.uid()`. Клиент его не выбирает.

## Переменные окружения

Файл `frontend/.env.local` (не коммитится):

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

Образец без значений: `frontend/.env.example`. Secret key и пароль базы во frontend не используются.

## Адреса страниц

- `/auth` — вход и регистрация
- `/tasks` — список и фильтр, только после входа
- `/tasks/new` — форма создания
- `/tasks/:id` — карточка задачи
- `/tasks/:id/edit` — форма редактирования
- `/unknown` — страница не найдена

## Текущие ограничения

Поиск по двум параметрам и связанные сценарии появятся в ЛР 7. Подтверждение email зависит от настройки проекта: если оно включено, после регистрации нужно перейти по письму и затем войти.

## Запуск

Из корня скачанного проекта:

```bash
cd frontend
npm ci
npm run dev
```

Откройте адрес из терминала (обычно `http://localhost:5173`).

Если `npm ci` тянет пакеты с чужого адреса, выполните:

```bash
npm install --registry https://registry.npmjs.org/
```

## Проверка сборки

Остановите dev через Ctrl+C. Выполните в `frontend`:

```bash
npm run build
npm run preview
```
